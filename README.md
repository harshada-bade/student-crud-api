# Student CRUD API

A REST API built with Python and Flask to manage student records.

---

## Prerequisites

- Python 3.9+
- [uv](https://docs.astral.sh/uv/getting-started/installation/) (Python package manager)
- Git

---

## Local Setup

### 1. Clone the repository
```bash
git clone https://github.com/harshada-bade/student-crud-api.git
cd student-crud-api
```

### 2. Install dependencies
```bash
make install
```

This runs `uv sync` which creates a `.venv` and installs all dependencies from `uv.lock`.

### 4. Configure environment variables
```bash
cp .env.example .env
```

Open `.env` and fill in your values:


### 5. Run database migrations
```bash
make migrate
```

### 6. Start the server
```bash
make run
```

Server runs at `http://127.0.0.1:5000`

### Students

| Method | URL | Description | Status Code |
|---|---|---|---|
| POST | `/api/v1/students` | Create a new student | 201 |
| GET | `/api/v1/students` | Get all students | 200 |
| GET | `/api/v1/students/<id>` | Get a student by ID | 200 |
| PUT | `/api/v1/students/<id>` | Update a student | 200 |
| DELETE | `/api/v1/students/<id>` | Delete a student | 200 |

---

### Request Body — POST and PUT

```json
{
    "name": "Alice Smith",
    "email": "alice@example.com",
    "age": 20,
    "grade": "A"
}
```

| Field | Type | Required | Rules |
|---|---|---|---|
| `name` | string | yes | max 100 characters |
| `email` | string | yes | must be unique |
| `age` | integer | yes | must be a number |
| `grade` | string | yes | max 2 characters |

---

### Response Example

```json
{
    "id": 1,
    "name": "Alice Smith",
    "email": "alice@example.com",
    "age": 20,
    "grade": "A"
}
```

---

### Error Responses

| Status Code | Meaning |
|---|---|
| 400 | Missing or invalid fields |
| 404 | Student not found |
| 409 | Email already exists |
| 500 | Internal server error |

## Running SQL Queries

> This section applies to local development only where `DATABASE_URL` points to SQLite. Production uses PostgreSQL.

### Connect to the local SQLite database
```bash
sqlite3 instance/students.db
```

### Available commands

```sql
-- See all tables
.tables

-- See all students
SELECT * FROM students;

-- See a specific student by ID
SELECT * FROM students WHERE id = 1;

-- See only names and emails
SELECT name, email FROM students;

-- Count total students
SELECT COUNT(*) FROM students;

-- Exit the SQLite shell
.quit
```

### One-Command Setup

```bash
make compose-up
```

This single command will:
1. Start the PostgreSQL database container
2. Wait until the database is healthy
3. Run database migrations automatically
4. Build the API Docker image
5. Start the API container

Once complete, the API will be available at `http://127.0.0.1:5000`

## Architecture Overview

This project is more than a Flask API — it includes a full DevOps stack running on a local Minikube cluster.

```
Developer pushes code
        │
        ▼
GitHub Actions CI
  ├── Run tests + lint
  ├── Build Docker image (tagged with git commit SHA)
  ├── Push to Docker Hub
  └── Update helm/application/values.yaml with new image tag
        │
        ▼
ArgoCD (GitOps)
  └── Detects values.yaml change → syncs Kubernetes deployment
        │
        ▼
Minikube Cluster (3 nodes)
  ├── minikube          → student-api (application node)
  ├── minikube-m02      → PostgreSQL, dependent services
  └── minikube-m03      → Grafana, Loki, Prometheus, ArgoCD
```

**Stack components:**

| Component | Purpose |
|---|---|
| Flask + PostgreSQL | REST API + persistent storage |
| Docker | Container image build |
| GitHub Actions | CI — test, build, push, update tag |
| ArgoCD | CD — GitOps-based deployment |
| Prometheus | Metrics collection |
| Grafana | Metrics and log dashboards |
| Loki + Promtail | Log aggregation from student-api pods |
| Blackbox Exporter | Endpoint uptime probing |

## Kubernetes / Minikube

### Cluster setup

The project runs on a 3-node Minikube cluster with node labels used for workload placement:

```bash
minikube start --nodes 3
kubectl label node minikube       type=application
kubectl label node minikube-m02   type=database
kubectl label node minikube-m03   type=dependent_services
```

### Deploy with ArgoCD (GitOps)

All Kubernetes resources are managed by ArgoCD. A push to `main` triggers CI, which updates the image tag in `helm/application/values.yaml`. ArgoCD picks up the change and syncs automatically.

To manually trigger a sync:
```bash
kubectl patch application student-api -n argocd \
  --type merge -p '{"operation": {"initiatedBy": {"username": "admin"}, "sync": {"revision": "HEAD"}}}'
```

### Check pod status

```bash
kubectl get pods -n student-api
kubectl get pods -n observability
kubectl get pods -n argocd
```

## CI/CD Pipeline

Defined in `.github/workflows/ci.yml`. Runs on every push that touches application code.

**Pipeline stages:**

1. **Lint** — runs `flake8` on `app/` and `tests/`
2. **Test** — runs `pytest` against the test suite
3. **Build & Push** — builds the Docker image tagged with the git commit SHA and pushes to Docker Hub
4. **Update image tag** — commits the new SHA into `helm/application/values.yaml`

**ArgoCD then:**
- Detects the values.yaml change in git
- Runs `db-migrate` initContainer (`flask db upgrade`) to apply any schema changes
- Rolls out the new pod

### Trigger the pipeline manually

The workflow supports manual dispatch from the GitHub Actions UI (`workflow_dispatch`).

---

## GitOps Flow

Direct `helm upgrade` against the cluster is **not used** — ArgoCD owns all Kubernetes resources via Server-Side Apply. The correct way to change anything in the cluster is:

```
Edit file → commit → push → ArgoCD syncs
```

This applies to:
- Image tag changes (handled automatically by CI)
- Helm values changes (e.g. replica count, resource limits)
- Kubernetes manifest changes

## Observability

### Access service UIs

```bash
make info
```

This prints live URLs and credentials for Grafana and ArgoCD, and reminds you of the port-forward commands for Prometheus and Alertmanager.

### Grafana

- URL: `http://<minikube-ip>:30119`
- Username: `admin`
- Password: retrieved via `make info`

**Datasources configured:**
- **Prometheus** — metrics (default datasource)
- **Loki** — logs from student-api pods

**Useful queries in Grafana (Explore → Loki):**

```logql
# All student-api logs
{service_name="student-api"}

# Warning-level logs (e.g. duplicate email attempts)
{service_name="student-api"} |= "WARNING"

# Error-level logs
{service_name="student-api"} |= "ERROR"
```

### Prometheus

ClusterIP — access via port-forward:

```bash
make prometheus-pf
# then open http://localhost:9090
```

Prometheus scrapes:
- Kubernetes node and pod metrics (via kube-state-metrics + node-exporter)
- PostgreSQL metrics (via postgres-exporter sidecar)
- Endpoint uptime (via Blackbox Exporter probing `/healthcheck`)

### Alertmanager

```bash
make alertmanager-pf
# then open http://localhost:9093
```

### Loki + Promtail

- Promtail runs as a DaemonSet on all nodes, shipping logs from `student-api` pods to Loki
- Logs are queryable in Grafana under the Loki datasource with `{service_name="student-api"}`
- Multi-tenancy is enabled with tenant ID `foo`

### Blackbox Exporter

Probes the following endpoints every 30 seconds and exposes results as Prometheus metrics:

| Target | Endpoint |
|---|---|
| student-api | `/healthcheck` |
| ArgoCD | `/healthz` |
